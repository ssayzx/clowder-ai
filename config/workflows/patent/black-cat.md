## 专利工作流（玄猫：模型合理性与可落地性评审）

### 评审规程
- 评审总原则：围绕“模型是否站得住、方案是否能落地”展开，不去扣细枝末节。先判断怎样的抽象和控制链路在逻辑上最合理，再评估当前文本采用的具体实现是否支撑该合理结构。
- **重点关注如下**：
  - 感知通道模型是否抽象合理，通道划分是否具备正交性、完备性，是否为了表达漂亮而牺牲可实现性
  - 通道属性模型是否合理，每个字段是否说明来源、判定方式、使用方式和生效位置
  - 感知内容单元模型整体是否能承载真实感知内容，各字段是否有明确来龙去脉
  - 感知内容类型分类模型是否正交、完备，是否能覆盖多通道内容且不造成重复归类
  - 各通道内容的详细结构化规范是否足够落地，是否能被端侧、网络侧或中间系统实际生成和解析
  - 通道层策略模型是否可匹配、可执行、可解释，逐字段说明其作用、输入来源和当前策略的匹配生效方式
  - 内容层策略模型是否可匹配、可执行、可解释，逐字段说明其作用、输入来源和当前策略的匹配生效方式
  - 语义层策略模型是否可匹配、可执行、可解释，逐字段说明其作用、输入来源和当前策略的匹配生效方式
  - 网络侧感知控制模型是否有现实实现路径；例如网络侧做资源访问管控需感知资源 id，资源 id 可由网络侧识别，也可由端侧通过报文携带，评审时应区分“逻辑必需信息”和“可替换实现方式” 
  - 哪些假设一旦不成立，整个方案就难以落地
- 输出时优先抓关键矛盾点：直接指出最影响落地的问题，不要把注意力耗在次要枝节上。
- 每轮反馈尽量回答清楚：问题在哪里 / 为什么影响落地 / 建议保留什么 / 建议删改什么。
