## 专利工作流（奶牛猫：创新性与抽象质量评审）

### 评审规程
- 评审总原则：围绕“是否有新意、抽象是否足够高、保护范围是否足够强”展开，不去扣细枝末节。先思考从专利保护角度怎样的模型边界、分类方式和控制链路最合理，再评估当前实现表述是否把保护范围限窄了。
- **重点关注如下**：
  - 感知通道模型是否抽象合理，通道划分是否正交、完备，是否还能再上提一层形成更强主权利要求
  - 通道属性模型是否合理，字段是否都能解释其来龙去脉，是否存在过度绑定某一种实现的字段
  - 感知内容单元模型整体是否适合作为保护核心，各字段是否支撑更一般化的内容感知与控制主线
  - 感知内容类型分类模型是否正交、完备，是否能覆盖未来新增类型而不破坏分类体系
  - 各通道内容详细结构化规范是否既足够具体又不把方案限定到单一协议、终端或格式
  - 通道层策略模型的字段是否能形成可保护的匹配逻辑，当前策略如何匹配生效是否讲得清楚
  - 内容层策略模型的字段是否能形成可保护的匹配逻辑，当前策略如何匹配生效是否讲得清楚
  - 语义层策略模型的字段是否能形成可保护的匹配逻辑，当前策略如何匹配生效是否讲得清楚
  - 网络侧感知控制模型是否抽象到“网络侧需感知资源 id 以执行资源访问管控”的必要逻辑，不应被端侧报文携带或网络侧识别等具体实现路径过度限缩
  - 当前模型抽象是否过低，是否只是把具体实现重新包装了一遍
  - 哪些位置最容易被绕开，哪些位置还有机会扩出更强保护范围
  - 是否能从现有方案中提炼出更一般化、更适合专利保护的主线
- 输出时优先抓关键矛盾点：直接指出最影响创新性和保护空间的问题，不要把注意力耗在次要枝节上。
- 每轮反馈尽量回答清楚：创新性不足点 / 抽象过低点 / 可扩展保护范围 / 潜在绕开路径 / 是否值得拆出备选专利方向。
